# D3.js in React

## Integration approach

Prefer **"D3 for math, React for DOM"**: use d3-scale, d3-shape, d3-array, d3-format, d3-time to compute positions and paths, and render `<svg>` elements with JSX. This keeps React in control and makes the chart testable.

Use **D3-owned DOM** (select a `ref` and let D3 append/join) only for features that genuinely need it: d3-zoom, d3-brush, d3-drag, d3-force simulations, or animated transitions on large selections. In that case:

```tsx
const ref = useRef<SVGGElement>(null);
useEffect(() => {
  if (!ref.current) return;
  const g = d3.select(ref.current);
  // join pattern
  g.selectAll('circle')
    .data(data, (d: any) => d.id)
    .join('circle')
    .attr('cx', d => x(d.x))
    .attr('cy', d => y(d.y))
    .attr('r', 4);
  return () => { g.selectAll('*').interrupt(); };
}, [data, x, y]);
```

## Conventions

- Margins convention: `{ top, right, bottom, left }`; inner width/height derived from container size.
- Memoize scales with `useMemo` keyed on data extent and size.
- Axes: render with `d3-axis` into a `<g ref>` or draw ticks with JSX from `scale.ticks()`.
- Number/date formatting via `d3-format` / `d3-time-format` with explicit locale.
- Import only the D3 modules you use (`import { scaleLinear } from 'd3-scale'`) to keep bundles small.

## Performance

- SVG is fine up to a few thousand elements. Beyond that, render marks to `<canvas>` and keep SVG for axes and annotations.
- Throttle pointer handlers; use `d3.bisector` or a quadtree (`d3-quadtree`) for hover lookup.

## Interaction

- Tooltips: a React-rendered absolutely positioned element driven by state, not D3-appended divs.
- Keyboard: allow focusing data points or provide arrow-key navigation for primary series.
